# Валидатор отчётности ПУРЦБ (УОД, XBRL-CSV 2.0)

Классическое Windows-приложение (WinForms, .NET 8) для проверки пакетов
учётно-операционных данных профессиональных участников рынка ценных бумаг
(ПУРЦБ) в формате **XBRL-CSV 2.0 Банка России** на соответствие
**таксономии УОД ПУРЦБ 6.1.0.10** (набор 20260403/20260430) и
**контрольным соотношениям ЦБ РФ**.

Входные данные — то, что формирует ваш конвертер:

* **mapping.json** — служебный файл пакета (описание таблиц и колонок);
* **CSV-файлы** — `sr_sved_purcb.csv` + `sr_R1.csv` … `sr_R11.csv`.

## Архитектура: четыре слоя валидации

### Слой 1 — структура mapping.json
Синтаксис JSON, строгий UTF-8, BOM, обязательные поля и форматы:
`@context`, `header` (кодировка, разделитель, ограничитель текста, `reportDate`
в ISO 8601, `documentVersion`, `textValueLengthLimit`, `identifier`,
`requestNumberDifp`), `dtsReferences`, перечень таблиц (`uri` — уникальность,
`csvRowsCount`, `roleUri`), колонок (`columnId` — уникальность), определение
формы описания (полная / краткая).

### Слой 2 — официальные JSON-схемы ЦБ (draft 2020-12)
mapping.json проверяется по **официальным схемам** draftSchema таксономии
(точка входа `ep_nso_purcb_oper_nr_uod_reestr.def.json`, схемы таблиц
`sr_*.def.json`, словари `dic/*.def.json`), входящим в поставку. Схемы
регистрируются по их `$id`, поэтому перекрёстные ссылки `$ref` разрешаются
офлайн. Так контролируются точный состав колонок, их порядок в части
осей (`prefixItems`), константы концептов, типы и периоды.

Содержимое массива `tables` проверяется **по-таблицно**: запись `tables[i]`
опознаётся по `roleUri` (запасной вариант — по `uri`) и сверяется напрямую
со схемой своей таблицы, поэтому замечания получают точные пути
`/tables/i/columns/j` и имя таблицы. Сквозная оценка через `anyOf` точки
входа в библиотеке JsonSchema.Net 9.7.0 даёт два дефекта: смещение
указателей инстанса (ошибки i-й записи приписываются пути (i−1)-й) и
развёртку каскада всех ветвей (~14 секунд и ~2 ГБ памяти на один
mapping.json), поэтому из схемы точки входа используется модифицированная
копия с каркасной заглушкой массива `tables` (сохраняются
`type`/`minItems`/`uniqueItems` самого массива).

### Слой 3 — CSV-данные
* наличие файлов пакета и лишние CSV в папке;
* кодировка UTF-8 (строгая), BOM;
* заголовок CSV против описания таблицы (пропавшие/лишние колонки, порядок);
* число строк данных против `csvRowsCount`;
* число полей в каждой строке, экранирование и ограничители текста;
* типы значений колонок (`integer`, `decimal`/`monetary`, `date`,
  `enum`/`enum2`) — для краткой формы маппинга тип берётся из таксономии;
* маркер отсутствия значения «-» пропускает проверки типов, масок и
  перечислений: правомерность отсутствия у конкретного элемента
  контролируют exists-правила ЦБ (слой 4);
* ограничение длины текстовых значений `textValueLengthLimit`;
* пробелы по краям значений.

### Слой 4 — бизнес-правила
1. **Контрольные соотношения ЦБ** — 261 из 317 официальных формул
   (valueAssertion / existenceAssertion из комплекта ЦБ «для проверки пакета
   на соответствие контрольным соотношениям», апрель 2026) переведены в
   исполняемый набор `Resources/rules.json`: обязательность полей при
   условиях, разрешённые/запрещённые значения, запрет заполнения,
   конъюнкции значений, маски, сравнения дат с отчётной датой. Семантика
   повторяет исходные SQL-выражения (в т.ч. то, что пустое значение при
   проверке `= / !=` тоже является нарушением). Пустая строка и маркер
   отсутствия «-» трактуются одинаково — как отсутствие значения. Остальные 56 формул
   (кросс-табличные и с внутренними переменными `gv001`) поставляются
   справочным каталогом `Resources/rules_reference.json`.
2. **Встроенные структурные проверки пакета**:
   * уникальность комбинаций осей `dim_int_*` в таблицах с `typedFiltering`;
   * согласованность сопроводительной информации (`sr_sved_purcb`) с составом
     таблиц: флаг «данные переданы / отсутствуют» против фактических строк;
   * ровно одна строка в `sr_sved_purcb`.
3. **Проверки таксономии**: домены перечислений (QName-значения членов,
   включая enum2 с URI-значениями) и фасеты XSD (маски значений вида
   `[1-2]`, `11[1-3]|12[1-2]|20[1-3]|999` и т.п.).

Все замечания несут слой, код, файл, таблицу, строку, колонку, метку
показателя из таксономии (например, «Дата заключения договора») и текст
на русском языке. Критичность: **ОШИБКА** / **ПРЕДУПРЕЖДЕНИЕ** (уровень
WARNING контрольных соотношений ЦБ) / **ИНФО**.

## Сборка и запуск

Требуется **SDK .NET 8** (Windows, Linux или macOS — WinForms-проект
собирается и на Linux благодаря `EnableWindowsTargeting`).

```bash
cd PurcbValidator
dotnet build                      # всё решение
dotnet test                       # 34 теста (~10 с)
dotnet run --project src/PurcbValidator.App    # Windows-приложение
dotnet run --project src/PurcbValidator.Cli -- samples/example_package --out report.xlsx
```

Публикация автономного exe для Windows:

```bash
dotnet publish src/PurcbValidator.App -c Release -r win-x64 --self-contained false -o publish
```

### Консольный запуск

```
purcb-validator <путь к mapping.json или папке пакета> [параметры]
  --no-schema      не проверять по официальным JSON-схемам ЦБ
  --rules <файл>   альтернативный файл правил rules.json
  --out <файл>     сохранить отчёт в .xlsx
  --quiet          печатать только сводку
```

Код возврата: 0 — пакет прошёл проверку, 1 — есть ошибки, 2 — сбой.

### WinForms-приложение

Укажите папку пакета или файл `mapping.json`, нажмите **«Проверить»**.
Результаты фильтруются по критичности и слою, двойной клик по строке —
полная карточка замечания. Кнопка **«Экспорт в Excel…»** сохраняет отчёт
(листы «Сводка», «Замечания», «Таблицы пакета»; автофильтр, закрепление
заголовков, подсветка критичности).

## Формат rules.json

```jsonc
{
  "rules": [
    {
      "id": "valueAssertion_R1_05",        // код формулы ЦБ
      "table": "sr_R1",                    // таблица
      "severity": "warning",               // warning | error
      "message": "Раздел 1. …",            // текст из комплекта ЦБ
      "check": "requiredIf",               // тип проверки (см. ниже)
      "column": "purcb_dic_Cntrct_Optn_dimGrp_1_periodGrp_1",
      "when": {                            // условия применимости к строке
        "anyFilled":  ["…"],               // хотя бы одна колонка заполнена
        "allFilled":  ["…"],               // все колонки заполнены
        "valueIn":    [ {"column": "…", "values": ["1","2"]} ],
        "valueNotIn": [ {"column": "…", "values": ["999"]} ],
        "valueMatches":[ {"column": "…", "pattern": "^[6-9]|10$"} ],
        "dateRules":  [ {"left": "$reportDate", "right": "…", "op": "ge"} ]
      }
    }
  ]
}
```

Типы проверок (`check`):

| Тип | Смысл |
|---|---|
| `required` / `requiredIf` | колонка обязательна (при выполнении `when`) |
| `requiredAnyOf` | обязательна хотя бы одна колонка из группы |
| `requiredIn` / `allowedValuesIf` | колонка обязательна и значение из списка |
| `requiredNotIn` / `forbiddenValuesIf` | колонка обязательна и значение НЕ из списка |
| `forbiddenIf` | колонка не должна заполняться при выполнении условий |
| `matchesPatternIf` | колонка обязательна и соответствует регулярному выражению |
| `valueConjunction` | все перечисленные условия на значения должны выполняться |

В `dateRules` поддерживаются `ge|gt|le|lt|eq`, стороны `$reportDate` или
колонка с датой, сдвиг в днях (`days`).

Набор правил подключается из ресурсов приложения; свой файл передаётся
параметром `--rules` (CLI) или `ValidationOptions.RulesFile` (API).

## Обновление под новую таксономию

Ресурсы валидатора получены скриптами из `tools/` (нужен Python 3.10+):

1. Скачайте с сайта ЦБ новые архивы (таксономия, draftSchema, правила).
2. `extract_taxonomy.py` — сборка `taxonomy_dict.json` (метки, домены
   перечислений, фасеты XSD) из таксономии;
3. `translate_rules.py` — перевод контрольных соотношений в `rules.json`
   (+ `rules_reference.json`); перед запуском поправьте пути к архивам;
4. Новые `*.def.json` скопируйте в `src/PurcbValidator.Core/Resources/cbr_schemas/`
   и обновите `EntryPointId` в `CbrSchemaValidator.cs` (при смене набора дат).

## Ограничения

* Реализована таксономия УОД ПУРЦБ 6.1.0.10 (набор 20260403/20260430);
  для других точек входа потребуются новые схемы (см. выше).
* 56 из 317 контрольных соотношений (кросс-табличные формулы и формулы
  с вычислимыми переменными `gv001`) не исполняются, а поставляются
  справочно в `rules_reference.json`; при необходимости их логику можно
  добавить собственными правилами в `rules.json`.
* Проверка соответствия XBRL-CSV спецификации OIM (трансформация в отчёт
  XBRL) не выполняется — валидатор проверяет пакет данных и правила ЦБ,
  а не полноту конвертации. Для финальной приёмки используйте также
  ПО Банка России («Конвертер», валидация контрольных соотношений).
